# 更高频下增加生成器垂向带宽：单一开发诊断

> 历史证据 / 技术参考（2026-10-05 归档标记）：保留原实验、数值和复现路径。
> 文内“当前/下一步/待完成”描述属于当时阶段，不是现行任务；请先读[三条 Wave as Prompt 路线](wave_as_prompt/README.md)。

> 2026-10-04在查看新32独立系统结果前记录。仅使用旧8开发环境，目标仍是高精度复相位。

现有频率曲线在800Hz显示：32深度项真实介质oracle，宽/窄源raw约0.00135/0.00215；
64深度项真实介质oracle降为约0.000124/0.000213。当前32项、128维推断代码约0.00351/
0.00356。差距为具体的表示带宽/推断机制线索，值得仅试一次“深度64项、相同128实代码”。

训练先验仍用原512训练介质标签，拟合64距离中心×64深度余弦项的rank128 PCA。环境代码维数
仍128；全局basis和训练标签变大，不宣称免费增精度。新先验初值只由旧8系统的32项context推断
值投影得到，不接触800Hz真值。然后读出到256段，同60/100/140Hz、65剖面再做固定5次全程GN；
预测时用128模态、384点积分，不按高频结果挑停止步。比较已经完成的32项代码、真介质32/64
oracle、完整介质oracle；140/400/800Hz全报告宽/窄两源与幅值/相位。

预期任何收益都先归给**线性统计先验的更高物理带宽**，不能算作新深神经方法。若更高带宽
不改善，检查容量投影oracle与context条件，停止进一步扫深度项/rank/step；若明显改善，也只
提出表示学习的机制问题，独立32新系统已经用于确认先前的32项版本，不能事后把64项回写成
它的预注册候选。真实SSP投影oracle继续作为额外信息诊断，不与部署方法混表。

## 已完成结果（旧8开发系统）

每行是系统等权的raw complex相对L2。`prior64`仍是128个环境实坐标，但全局统计基、训练介质标签和读出系数都更大；它不是深网络。`projection oracle`使用真实环境在64项PCA子空间的投影，不由观测反演，且不是响应误差的数学下界。

| 频率与声源 | 原32项推断 | 64项推断 | 64项投影oracle |
|---|---:|---:|---:|
| 140Hz宽源 | 0.000093 | 0.000092 | 0.000267 |
| 140Hz窄源 | 0.000817 | 0.000348 | 0.000285 |
| 400Hz宽源 | 0.001185 | 0.001112 | 0.000905 |
| 400Hz窄源 | 0.001552 | 0.001274 | 0.000924 |
| 800Hz宽源 | 0.003508 | 0.002902 | 0.001814 |
| 800Hz窄源 | 0.003556 | 0.002841 | 0.001901 |

800Hz平均误差分别下降17.3%和20.1%，逐系统宽源6/8、窄源8/8获益；首个系统的宽源却从0.009327变差到0.009575，不可只报告平均。真实64项介质的额外信息oracle在旧512段读出下为0.000124/0.000213；它与本表256段方法并非同一数值设置。另一个边界闭合实验中的256段匹配oracle为0.000311/0.000375。

结论：固定代码维数不等于固定全局表示/推断/解码成本；增加垂向带宽有益，但旧8环境上的增益不足以把它独立提升为新的学习贡献，更不能事后把它写成新32独立环境的冻结候选。逐系统数字与幅值/相位指标见`../artifacts/coherent_waveguide_depth64_800_dev_20261004/`。
