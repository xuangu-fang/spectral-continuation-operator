## 只回答一个问题

在taper10新16环境，训练taper5的rank256真介质**欧氏投影**800Hz宽/窄raw仍0.2925/0.2789，部署法0.4155/0.4350；真实32深度项投影oracle仅约0.0028。欧氏投影不最小化波场误差，不能用其失败证明256维子空间本身必定缺乏容量。本诊断让这个**冻结PCA256子空间读取800Hz目标宽源复响应后，直接优化同一坐标**，问它能否使目标响应明显更准。

## 固定做法与解释边界

- 对全部原16个已看过的taper10系统，不筛系统；同训练512介质先验、相同256维子空间，不重新训练或扩rank。初值额外读取真实介质并作欧氏PCA投影，这是oracle信息。
- 再额外读取**目标800Hz宽源**的257条完整深度剖面（64模态teacher，256传播段边界）。已知源解析初态；在256距离段×32深度项、64传播模态下，按原`ridge_relative`、系数步长及线搜索做固定5次Gauss–Newton。每步记录目标宽源和**未用于拟合**的新2m窄源，在原4097×513真值和完整>=50m ROI评价raw complex RelL2与相位。
- 只在这个oracle目标宽源上拟合，**不能**称为从低频context推断，也不能把窄源结果称为完全干净的zero-shot（隐代码已通过同频宽源目标泄漏）。它是表示子空间的局部响应适配诊断，不是全局最优的容量下界；5步未收敛或源交叉退化都要如实保留。
- 若5步后宽源raw能降到≤0.05，说明先前欧氏投影高误差不能用来称子空间不足；若宽源仍>0.10，仅能说**当前固定局部优化未证实容量充足**，不能断言任意代码均失败。窄源用于判断这种目标拟合是否仍像物理系统表示一样可跨源。阈值只为解释分叉，不改变原OOD失败的预设门槛。

配置：[JSON](../configs/coherent_waveguide_spectral_taper_response_oracle_20261004.json)；实现：`src/spectral_continuation/audit_waveguide_spectral_taper_response_oracle.py`。代码和配置须在运行/读取新的逐步适配结果前提交。

## 完成结果：单一响应可补偿很多，但系统代码仍不保真

全部16个先前已看过的OOD环境、固定5步完成；每步均保留宽源与新窄源完整ROI的raw和相位。5步后：

| 800Hz，16环境等权 | 真实介质欧氏PCA256投影，step0 | 只用目标宽源适配5步 | 真实32项物理oracle |
|---|---:|---:|---:|
| 宽源raw / 相位rad | 0.29251 / 0.24021 | **0.07536 / 0.05620** | 0.00285 / 0.00238 |
| 新窄源raw / 相位rad | 0.27887 / 0.23000 | **0.22321 / 0.18228** | 0.00281 / 0.00232 |

宽源5步后只有3/16系统raw≤0.05、14/16≤0.10；窄源0/16≤0.05、1/16≤0.10。宽源从step0至5的raw依次为0.2925→0.1428→0.0966→0.0840→0.0772→0.0754；窄源为0.2789→0.2249→0.2190→0.2216→0.2230→0.2232。5步末1/16系统未接受进一步下降的线搜索步长，不能说全部收敛。所有连续数字见同名artifact的`summary.json`与`results.json`。

它给出比原欧氏oracle更精确的结论：**欧氏PCA投影0.29绝不是该256维空间的最佳单场响应误差**；直接读取目标宽源可以把它降至0.075。可惜这仍不达预设的高精度0.05均值，而未拟合的窄源仍约0.22，明显不像一个已获得的可靠共享系统表示。但本实验故意没给窄源目标，不能把其高误差直接解读成“两源共同代码不可能”。因此只再做一次[已登记、同样目标泄漏的双声源共同oracle](SPECTRAL_TAPER_JOINT_ORACLE_ZH.md)，之后停止这条事后oracle分支；无论其结果如何，原低频部署OOD失败不变。
